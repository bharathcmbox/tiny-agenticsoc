Ask your SOC in plain language

Type a question like "which processes touched lsass.exe today, and what started them?". An AI analyst searches your SIEM and network telemetry with read-only tools, then answers with the exact events that prove it.

There are two ways in, over the same data and the same tools. SOC console is a search bar in the browser, with nothing to install. Claude Code connects your own Claude over MCP, so your engineers can investigate from their terminal.

What happens when you ask

  1. You ask in the console. Plain language, up to 600 characters. Example questions are one click away.
  2. The gateway checks access. Every request needs a token. Guests get a daily trial budget on the lab's key and a rate limit, or they paste their own Anthropic key, which is used for that request and never stored.
  3. The Ask agent plans. Claude Sonnet 5.5 decides what to look for. You watch each step live in the trace panel.
  4. It calls read-only tools. Search alerts and raw events, rebuild a process tree from Sysmon, pull Zeek and Suricata flows, count top values.
  5. The tools query the SIEM. They go through an SSH tunnel as a read-only indexer user. The SIEM is never exposed on the network, and there is no write path.
  6. You get a cited answer. The direct answer first, then an evidence table (time, host, source, field values), a confidence level and suggested follow-up questions.
  7. The cost is logged. Every answer shows its price and who paid. The ledger enforces daily caps per guest.

Or bring your own Claude

  1. Add the MCP server to Claude Code. One command, which the console's Connect Claude Code tab shows with your token filled in: 
    claude mcp add --transport http tiny-soc https://<console>/mcp/ --header "Authorization: Bearer <token>"
  2. Claude Code calls the same tools. The same seven read-only tools, the same guardrails, the same token check.
  3. Results come back to your terminal. Your Claude does the reasoning, so the lab spends nothing. It suits engineers who want to pivot, script and dig deeper.

Questions that work well

  • Which processes accessed lsass.exe today, and what started them?
  • What happened on lin-victim in the last 24 hours?
  • Was any event log cleared? By whom and when?
  • Which external domains did win-victim resolve today?
  • Summarise today's incidents and what you'd verify next.

Try it in five minutes

SOC console

  1. Open the link you were sent. It carries your access token, or the console asks for it.
  2. Click an example question, or type your own.
  3. Watch the trace panel: each tool call, how long it took, how much data came back.
  4. Read the answer and its evidence table. Click a follow-up to keep pulling the thread.
  5. Open Incidents to read the investigation agent's reports on what the pipeline detected.
  6. Out of trial budget? Use Use my Anthropic key to continue on your own key.

Claude Code

  1. Install Claude Code if you don't have it.
  2. Copy the claude mcp add … command from the console's Connect Claude Code tab.
  3. Start claude and run /mcp to confirm that tiny-soc is connected.
  4. Ask: "List the incidents, then rebuild the process tree for the LSASS dump on win-victim."
  5. Keep going: ask it to write a detection rule for what it found, or a timeline for a report.

Why you can trust the answers

  • Read-only by construction. The indexer user cannot write. No tool changes a host. Containment is only ever proposed for a human to approve.
  • Evidence, not vibes. Answers cite timestamps, hosts and field values from raw events, and say what was not checked.
  • Everything is visible. Each tool call appears in the trace, and every answer shows its cost and the model that produced it.
  • Open source underneath. Wazuh, Sysmon, Zeek, Suricata and Atomic Red Team. Claude adds the analyst.

Where it runs today

  • A single laptop: Hyper-V VMs for the victims, sensor and SIEM, and WSL2 for the agents and console.
  • The console listens on localhost. Sharing it with others is a networking step (Tailscale or Cloudflare Tunnel). Token checks, rate limits and spend caps are already in place.
  • Models are one line of configuration: Claude through the Anthropic API by default, or any OpenRouter model.
