An agentic SOC on one laptop

A small but realistic security operations center: real endpoint and network telemetry, a real SIEM, real (contained) attacks, and LLM agents that triage and investigate the alerts, with a human approving every response.

Almost everything is open source. The lab runs on a single Windows 11 laptop under Hyper-V, so hosting costs nothing; the only spend is LLM tokens: about $0.0008 to triage an alert bundle and $0.04 to $0.10 to investigate an incident.

Follow one attack through the system

Take a single technique, T1059.001 (malicious PowerShell), from the moment it runs to the moment the case closes.

  1. Simulate. The eval harness asks Invoke-AtomicRedTeam on win-victim to run T1059.001 and records what it expects to be detected.
  2. Generate. Sysmon logs a process-create event (ID 1) with the full command line and parent process, and Windows logs PowerShell script block event 4104. If the script calls out to the internet, Zeek logs the connection and DNS query, and Suricata may fire a signature. Both stamp the same community_id on the flow.
  3. Ingest. The Wazuh agent forwards the events over port 1514. On the manager, decoders turn them into fields and rules give them a level. A suspicious PowerShell rule might reach level 10 or higher.
  4. Store. Filebeat writes the alert to wazuh-alerts-*, and every raw event, alerting or not, to wazuh-archives-*.
  5. Triage. The poller picks up the new alert (level 7 or above) and groups it with related alerts from the same host and time window. A small, cheap model maps it to ATT&CK and gives a verdict: benign, suspicious or escalate.
  6. Investigate. On escalation, a stronger model runs a tool-use loop. It rebuilds the process tree from Sysmon, pivots on the community_id into Zeek and Suricata, checks IPs and hashes against threat intel, and writes up what happened.
  7. Record. The agent opens a DFIR-IRIS case with the timeline, evidence, IOCs and a proposed response.
  8. Act. You approve or reject. On approval, the agent calls the Wazuh API and the manager pushes the active response, for example killing the process or isolating the host.
  9. Measure. The harness checks the result: was it detected, was the verdict right, how long did it take, and how many tokens and dollars did it cost.

Guardrails

Containment. All victim traffic leaves through sensor-gw, which drops anything bound for private, CGNAT or link-local ranges. Attacks can reach the internet but not the home network or the laptop. The host also blocks unsolicited inbound traffic from the lab.

Visibility. Victim NICs are Hyper-V port-mirror sources, so the sensor also sees lateral, victim-to-victim traffic that never touches the gateway.

Cost. Hosting is free. LLM calls only go out for alerts at level 7 or above, cheap models handle triage, and the OpenRouter account has a hard credit cap. Each case records its own token cost.

Authority. Agents read freely, but every action on the lab needs a human click.

Roadmap

Phase 0
done Hyper-V switch and VMs, NAT and containment, Zeek and Suricata with community-id, verified with a test alert.
Phase 1
done Wazuh all-in-one with archives on, agents grouped as sensor, linux and windows, Sysmon, auditd, local Zeek rules.
Phase 2
done 17 atomics with Defender on, a coverage matrix that subtracts harness noise, and new rules for LSASS dumping, cron, setuid, schtasks and log clearing: 7 of 17 detected became 12 of 17.
Phase 3
in progress Poller, triage and investigation agents, MCP tool server, DFIR-IRIS cases, approval-gated active response.
Phase 4
planned Eval harness: scheduled atomics produce a scorecard of detection, verdict accuracy, latency and cost per alert.
