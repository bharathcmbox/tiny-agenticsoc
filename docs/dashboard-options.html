Putting "Ask the SOC" inside the Wazuh dashboard

Today you open two separate things: the Wazuh dashboard at https://10.10.10.10 and the SOC console at http://localhost:8800. All three options below reuse the same Ask agent, tools and tokens. They differ only in how the search box gets onto Wazuh's pages.

Option A, step by step: what happens when you ask from a Wazuh page

The same flow in words

  1. You open the dashboard at https://localhost:8443 instead of https://10.10.10.10. You log in to Wazuh exactly as before.
  2. The proxy passes every request to the real Wazuh dashboard, untouched.
  3. When Wazuh returns an HTML page, the proxy adds a single <script> line. Data, API calls and images pass through untouched.
  4. Your browser shows the normal Wazuh page.
  5. The added line loads the search bar script. The proxy sends anything under /tsoc/ to the SOC console instead of to Wazuh.
  6. You press Ctrl+K (or click the bar) and ask. The question goes to the console with your console token, so the same caps and rate limits apply.
  7. The Ask agent plans with Claude and queries the Wazuh indexer through the read-only tools, exactly as in the console.
  8. The answer streams back into a panel over the page you were looking at. It shows the tool trace, the answer, the evidence and the cost.

Why a proxy at all? The Wazuh dashboard has a content security policy. It runs scripts and calls APIs only from its own address. Putting the dashboard and the search bar behind one address (the proxy) makes the bar count as "its own". The alternative, editing Wazuh's files, would break on every upgrade.
